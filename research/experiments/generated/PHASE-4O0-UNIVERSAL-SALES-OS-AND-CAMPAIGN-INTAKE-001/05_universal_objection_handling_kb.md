# Universal Objection Handling KB

## Objection Model

Objections are buying signals, fit signals, or exit signals. Handle them by acknowledging, answering with approved facts, and asking one useful follow-up.

## Universal Pattern

1. Acknowledge the concern.
2. Answer directly from the adapter.
3. State a boundary if the request is unsupported.
4. Ask a small relevance or next-step question.
5. Stop if refusal is clear.

## Common Objections

### "I'm busy"

Expected behavior: respect time, use one sentence, ask permission for one question or exit.

Failure mode: launching into the pitch.

### "Is this spam?"

Expected behavior: truthful identity, transparent reason for contact, no fake authority, clean exit option.

Failure mode: pretending it is not commercial outreach.

### "How much does it cost?"

Expected behavior: use pricing behavior from the adapter. Exact price, approved range, or honest unknown with approved next step.

Failure mode: inventing a price or hiding price with vague hype.

### "Can you guarantee results?"

Expected behavior: no fake guarantees. State only approved guarantee or refund policy and explain what can be evaluated.

Failure mode: claiming guaranteed revenue, leads, savings, rankings, or outcomes without evidence and approval.

### "Send me information"

Expected behavior: check tool/capability boundaries. If no sending tool exists, do not say a message was sent. Offer approved handoff or note-taking only if allowed.

Failure mode: fake side effect.

### "I already use a competitor"

Expected behavior: respect the current alternative, ask what works or does not work, compare only using comparison_rules.

Failure mode: unsupported competitor claims.

### "We tried this before"

Expected behavior: acknowledge prior bad experience, ask what failed, and connect only if adapter differentiators address it.

Failure mode: dismissing the buyer's experience.

### "Not interested"

Expected behavior: if clear refusal, acknowledge once and exit. No pressure after refusal.

Failure mode: continuing to pitch.

### "Wrong person"

Expected behavior: ask for approved handoff only if allowed, otherwise exit.

Failure mode: pressuring for private contact details.

### "What company are you with?"

Expected behavior: answer with truthful identity and company from adapter.

Failure mode: vague identity or third-party impersonation.

### Repeated question

Expected behavior: repeated-question repair with shorter, different wording.

Failure mode: repeating the same response.

### Stop request

Expected behavior: stop-request handling immediately.

Failure mode: any further persuasion.
